# AI Food Scanner — MVP Architecture & Technical Design

**Target Audience:** Indian consumers (with an initial focus on Kerala supermarket shoppers)  
**Primary Platform:** Mobile (iOS & Android via Expo / React Native) + Backend (Node.js / Express / TypeScript)  
**Database:** PostgreSQL (with Supabase / Prisma / standard PostgreSQL compatibility)  
**Language Support:** English & Malayalam (extensible to Hindi, Tamil)

---

## 1. Executive Summary & Core Philosophy

The **AI Food Scanner** enables Indian consumers, specifically starting with Kerala shoppers, to create a personalized health profile (diabetes, hypertension, cholesterol, dietary preferences, allergens) and scan packaged food products in supermarkets using their phone camera (barcode scan or nutrition label OCR).

### Non-Negotiable Medical Safety Guarantees
1. **Not a Doctor / Diagnostic Tool:** The application provides *nutrition-based decision support heuristics* and never diagnoses illnesses or prescribes/modifies medication.
2. **Deterministic Health Rules:** Recommendations are generated by a **pure deterministic rule engine**, *never* by an unconstrained LLM inventing health thresholds.
3. **Restricted AI Layer:** 
   - **Stage 1 (Vision/OCR):** Strictly extracts nutrition facts and ingredients into structured JSON validated by Zod schemas.
   - **Stage 2 (Explanation):** Formats and summarizes the deterministic rule engine's findings into conversational, friendly English or Malayalam. The AI is explicitly constrained from fabricating medical claims.
4. **Allergen Caution:** Allergen detection triggers clear alerts. Products are never marked "allergen-free" unless verified by source data.
5. **No Medical Evaluation of Medicines in MVP:** Medication fields are stored for future user records only; the MVP explicitly clarifies that food-medication interactions are not evaluated.

## 3. Database Schema

The schema uses strong relational integrity, normalization for nutrition values (both per 100g and per serving), and complete user isolation.

### 3.1 Tables Overview

```sql
-- 1. Users & Authentication
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. User Profiles
CREATE TABLE user_profiles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name VARCHAR(120) NOT NULL,
    age INT CHECK (age > 0 AND age < 130),
    gender VARCHAR(20), -- 'male', 'female', 'other', 'prefer_not_to_say'
    height_cm NUMERIC(5,2),
    weight_kg NUMERIC(5,2),
    country VARCHAR(60) DEFAULT 'India',
    state VARCHAR(60) DEFAULT 'Kerala',
    language_preference VARCHAR(10) DEFAULT 'en', -- 'en' or 'ml'
    disclaimer_acknowledged BOOLEAN DEFAULT FALSE,
    disclaimer_acknowledged_at TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. Master Health Conditions
CREATE TABLE health_conditions (
    code VARCHAR(50) PRIMARY KEY, -- 'diabetes', 'prediabetes', 'hypertension', 'high_cholesterol', 'weight_management', 'heart_health', 'other'
    name_en VARCHAR(100) NOT NULL,
    name_ml VARCHAR(100) NOT NULL,
    description_en TEXT,
    description_ml TEXT,
    is_active BOOLEAN DEFAULT TRUE
);

-- 4. User Health Conditions Mapping
CREATE TABLE user_health_conditions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    condition_code VARCHAR(50) NOT NULL REFERENCES health_conditions(code),
    notes TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    UNIQUE(user_id, condition_code)
);

-- 5. Master Dietary Restrictions & Allergens
CREATE TABLE dietary_restrictions (
    code VARCHAR(50) PRIMARY KEY, -- 'vegetarian', 'vegan', 'eggetarian', 'milk', 'lactose', 'peanut', 'tree_nuts', 'soy', 'wheat_gluten', 'egg', 'fish', 'shellfish', 'sesame'
    type VARCHAR(20) NOT NULL, -- 'preference' or 'allergen'
    name_en VARCHAR(100) NOT NULL,
    name_ml VARCHAR(100) NOT NULL,
    is_active BOOLEAN DEFAULT TRUE
);

-- 6. User Dietary Restrictions & Allergies Mapping
CREATE TABLE user_restrictions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    restriction_code VARCHAR(50) REFERENCES dietary_restrictions(code),
    custom_text VARCHAR(200), -- For custom allergens/restrictions
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 7. User Medications (Informational only, not evaluated for interactions in MVP)
CREATE TABLE user_medications (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    medicine_name VARCHAR(200) NOT NULL,
    dosage VARCHAR(100),
    frequency VARCHAR(100),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 8. Packaged Food Products
CREATE TABLE products (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    barcode VARCHAR(64) UNIQUE,
    name VARCHAR(255) NOT NULL,
    brand VARCHAR(255),
    category VARCHAR(100),
    serving_size VARCHAR(50),
    serving_size_unit VARCHAR(20),
    image_url TEXT,
    source VARCHAR(50) DEFAULT 'internal', -- 'internal', 'openfoodfacts', 'ocr_extracted'
    source_confidence NUMERIC(3,2) DEFAULT 1.0,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 9. Product Nutrition (Normalized to per 100g and per serving)
CREATE TABLE product_nutrition (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    product_id UUID NOT NULL REFERENCES products(id) ON DELETE CASCADE,
    basis VARCHAR(20) NOT NULL, -- 'per_100g' or 'per_serving'
    energy_kcal NUMERIC(7,2),
    carbohydrates_g NUMERIC(6,2),
    sugars_g NUMERIC(6,2),
    added_sugars_g NUMERIC(6,2),
    protein_g NUMERIC(6,2),
    fat_g NUMERIC(6,2),
    saturated_fat_g NUMERIC(6,2),
    trans_fat_g NUMERIC(6,2),
    fibre_g NUMERIC(6,2),
    sodium_mg NUMERIC(7,2),
    salt_g NUMERIC(6,2),
    UNIQUE(product_id, basis)
);

-- 10. Product Ingredients & Extracted Allergens
CREATE TABLE product_ingredients (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    product_id UUID NOT NULL REFERENCES products(id) ON DELETE CASCADE,
    raw_ingredients_text TEXT,
    parsed_ingredients JSONB, -- Array of ingredient strings
    detected_allergens JSONB, -- Array of detected allergen codes
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 11. Configurable Health Heuristic Rules
CREATE TABLE health_rules (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    condition_code VARCHAR(50) NOT NULL REFERENCES health_conditions(code),
    nutrient VARCHAR(50) NOT NULL, -- 'added_sugars_g', 'sugars_g', 'sodium_mg', 'saturated_fat_g', 'trans_fat_g', etc.
    basis VARCHAR(20) DEFAULT 'per_100g',
    operator VARCHAR(10) NOT NULL, -- '>', '>=', '<', '<='
    threshold NUMERIC(8,2) NOT NULL,
    severity VARCHAR(20) NOT NULL, -- 'low', 'moderate', 'high', 'critical'
    deduction INT NOT NULL DEFAULT 15,
    message_en TEXT NOT NULL,
    message_ml TEXT NOT NULL,
    advice_en TEXT,
    advice_ml TEXT,
    is_active BOOLEAN DEFAULT TRUE
);

-- 12. Scan History
CREATE TABLE scan_results (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    product_id UUID REFERENCES products(id) ON DELETE SET NULL,
    scan_type VARCHAR(20) NOT NULL, -- 'barcode' or 'ocr_label'
    assessment_status VARCHAR(30) NOT NULL, -- 'GOOD_CHOICE', 'USE_CAUTION', 'NOT_A_GOOD_CHOICE'
    score INT NOT NULL,
    reasons_json JSONB NOT NULL,
    allergen_warnings_json JSONB NOT NULL,
    nutrition_snapshot JSONB NOT NULL,
    ai_explanation_en TEXT,
    ai_explanation_ml TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 13. Saved / Favourites
CREATE TABLE saved_products (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    product_id UUID NOT NULL REFERENCES products(id) ON DELETE CASCADE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    UNIQUE(user_id, product_id)
);
```

## 4. Deterministic Rule Engine Architecture

The rule engine resides entirely in backend TypeScript modules and does **not** rely on LLMs to make rule evaluations.

### Input Data
- **User Health Snapshot:** `string[] conditions`, `string[] dietaryPreferences`, `string[] allergenRestrictions`
- **Product Snapshot:** `NutritionValues (per 100g)`, `string[] ingredients`, `string[] detectedAllergens`
- **Rule Set:** Active rules from the database or default heuristics configuration.

### Evaluation Workflow
1. **Base Score Initialization:** Start at `100`.
2. **Allergen & Restriction Matching:**
   - Case-insensitive substring and semantic tag match on user allergens vs. ingredients and `detectedAllergens`.
   - If match found: Flag `ALLERGEN_WARNING` with `severity: critical`, deduction of `40` points.
3. **Health Condition Heuristics:**
   - *Diabetes / Prediabetes:* Check `added_sugars_g` (> 5g per 100g = moderate, > 10g per 100g = high, > 22.5g = critical), check `carbohydrates_g` vs `fibre_g` ratio.
   - *Hypertension:* Check `sodium_mg` (> 400mg per 100g = moderate, > 600mg per 100g = high, > 900mg = critical).
   - *High Cholesterol:* Check `saturated_fat_g` (> 3g per 100g = moderate, > 5g = high) and `trans_fat_g` (> 0.2g = high, > 0.5g = critical).
   - *Weight Management:* Check `energy_kcal` (> 400 kcal per 100g = moderate) and `sugars_g`.
4. **Final Scoring & Status Mapping:**
   - **Score >= 80 & No Critical Warnings:** `GOOD_CHOICE` (🟢)
   - **Score 50-79 or Moderate Warnings:** `USE_CAUTION` (🟡)
   - **Score < 50 or Critical Allergen/Nutrient Warnings:** `NOT_A_GOOD_CHOICE` (🔴)
5. **Output Structure:**
   ```typescript
   export interface RuleEvaluationResult {
     status: 'GOOD_CHOICE' | 'USE_CAUTION' | 'NOT_A_GOOD_CHOICE';
     score: number;
     reasons: Array<{
       conditionCode: string;
       nutrient: string;
       severity: 'low' | 'moderate' | 'high' | 'critical';
       messageEn: string;
       messageMl: string;
       betterChoiceAdviceEn?: string;
       betterChoiceAdviceMl?: string;
     }>;
     allergenWarnings: Array<{
       allergen: string;
       matchedIngredient: string;
       isDefinite: boolean;
       messageEn: string;
       messageMl: string;
     }>;
   }
   ```

## 5. AI Vision & OCR Extraction Pipeline

### Stage 1: Nutrition & Ingredient Label Extraction (Strict JSON)
```typescript
export interface ExtractedProductLabel {
  product_name: string | null;
  brand: string | null;
  serving_size: string | null;
  nutrition_per_100g: {
    energy_kcal: number | null;
    carbohydrates_g: number | null;
    total_sugars_g: number | null;
    added_sugars_g: number | null;
    protein_g: number | null;
    total_fat_g: number | null;
    saturated_fat_g: number | null;
    trans_fat_g: number | null;
    fiber_g: number | null;
    sodium_mg: number | null;
    salt_g: number | null;
  };
  ingredients: string[];
  allergens: string[];
  extraction_confidence: number;
}
```
**Strict Zod Schema:** Ensures that if values are missing or unreadable, they are marked `null` and not hallucinated.

### Stage 2: Friendly Explanation Layer
- Input to LLM: **Only** the structured rule results and product name. No user PII (names, emails, unneeded medications) is sent.
- Guardrails System Prompt:
  - You are a helpful nutrition assistant explaining packaged food facts.
  - You must NOT provide medical diagnoses or alter medications.
  - You must only explain the supplied rule reasons in simple, encouraging language.
  - Provide both English and Malayalam summaries.

## 7. Security, Privacy & Compliance

1. **Zero Raw Health Data to AI:** When asking the LLM to write a 2-sentence user explanation, the prompt only receives anonymized rule flags (e.g. `flag: high_sugar`, `condition: blood_sugar_management`), omitting the user's name, email, age, or medications.
2. **Account Deletion & Data Portability:** Endpoints `DELETE /me` and `GET /me/export` are built-in from Milestone 1.
3. **No Credential Exposure:** Secret AI keys and database URLs reside purely on the backend.
4. **Transport Security:** All client-backend interactions mandate HTTPS.
5. **No Medical Claims:** Persistent non-intrusive disclaimer across scan results and onboarding.

## 8. Out of Scope for MVP (Explicit Boundaries)
- No automated food-medication interaction scoring.
- No direct medical diagnoses or disease curing statements.
- No meal planning, calorie counting, or macro tracking.
- No grocery ordering or delivery integrations.
- No doctor consultation chats or clinical review workflows.
